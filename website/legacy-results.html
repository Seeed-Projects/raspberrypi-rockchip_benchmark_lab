MPP 仍然保持较高画质，但其 SSIM 略低于 libx264。由于实际输出码率也更低，因此这里不能视为严格等码率画质对比。

What this means

  • 如果你只看 CPU 软件编码，RK3588 比 Pi 5 更强，但差距并不是数量级。
  • 真正改变结果的是 RK3588 的专用 H.264 硬件编码器（MPP）。
  • MPP 在 4K 编码任务上显著降低 CPU 负载，更适合需要同时运行其他 AI / I/O / 应用任务的边缘设备。
  • MPP 的压缩效率与软件编码并不完全等同，画质、码率和吞吐量之间存在权衡。

Recommended On-Screen Conclusion

Takeaway 01
Pi 5 vs RK3588 CPU encoding: RK3588 is faster, but both are far from real-time 4K30 in pure software encoding.
Takeaway 02
MPP changes the game: RK3588 nearly reaches real-time 4K30 with much lower CPU overhead.
Takeaway 03
There is a trade-off: hardware encoding is faster and lighter, but software encoding remains slightly stronger in compression efficiency.
